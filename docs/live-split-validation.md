# Bounded live split-lead acceptance

This is a manual test specification, not an automatic job. Use a separate private `DORI_HOME`, the frozen reviewed CLI, the current protected conversation ID and the existing local shared socket. Never use production tasks, messenger accounts or approval answers. Never restart the shared server or interrupt the conversation. Keep failures and compare actual native persisted items, not command success alone.

1. Start `up --connect SOCKET --lead CONVERSATION --split --cwd FIXTURE`. Read `roles.json`: conversation must equal the selected existing chat, work lead must be different, duty has no model role. Use the app title tool to set actual work lead to `🐾dori/업무 lead · studio` and worker to `🐾dori/방향 변경 시험`. Confirm native names. Tell the work lead this is a bounded validation fixture and that it should coordinate only this test, inspect evidence and close only its current instance/revision.
2. Create one brief and `start split-live --brief FILE --cwd FIXTURE`. The brief should run `task show split-live`, retain its native thread ID, ACK revision1 with `--instance THREAD`, and send one nonce-bearing `report ... --instance THREAD --revision 1`. It then runs a harmless local Python command that writes its PID and nonce in FIXTURE and waits at most20seconds. No formal goals or automatic audits. After the wait, follow the latest TASK REVISION; do not request broader permissions if any command fails.
3. While the fixture command is actually running, issue `pivot split-live --expected-revision 1 --text '...nonce... Implement the revision2 marker only. First demonstrate revision1 READY is refused; then ACK revision2, write revision2 proof and READY with --instance THREAD --revision2 and evidence file.'` Spaces are required: the real flags are `--revision 2`. Verify the returned current instruction is delivered, the exact native `turn/steer.expectedTurnId` matches the existing owned worker turn, and that the bounded command was not interrupted or replaced. Delivered must remain distinct from ACK until the worker actually confirms the new direction.
4. Let the bounded command finish naturally. Verify stale `ready ... --revision 1` failed, `ack ... --instance THREAD --revision 2` succeeded, the stored instruction is acknowledged, only revision2 proof exists and READY has final.revision2. Attempting stale/future ACK, report or READY must not change current state. A worker blocked on a native approval must instead retain its pivot queued; do not answer the approval to make the test pass.
5. Have the internal work lead inspect the exact fixture evidence and `done split-live --instance THREAD`. Routine START/REPORT/READY must appear in the internal lead's native user input, and must not appear in the conversation's native user input. The normal completion collector can be flushed explicitly with `duty --once`, wait at least5seconds after DONE, then `notifications flush`; or allow normal duty. There must be one short `[도리 업무 보고]` containing the completion nonce, not a raw report or operational receipt command. Root must actually receive this report. Inspect native `thread/items/list` entries through `entry.item` and userMessage.clientId; bound any readback polling because first items may appear just after the new turn becomes visible. Do not resend to compensate for a temporarily absent first item.
6. Read `notifications list`; match the submitted batch's immutable message to the report actually received, then `notifications ack BATCH_ID`. Confirm submission and root receipt are separate records. Repeat `duty --once` and `notifications flush`: no duplicate report. Stop only the isolated Dori wrapper and restart with `up` without flags. Both role IDs, task revision/ACK/outbox receipt persist, and no synthetic second work lead or duplicate completion appears.
7. Close any remaining fixture registrations locally and `down` the isolated wrapper. Confirm the native conversation and original shared-server PIDs remain alive. No live messenger test is part of this acceptance; upstream transport tests are injected offline HTTP/socket fixtures.

For a real idle-wake check, arm a bounded one-shot observer for this exact conversation turn and end it. If normal user input advances the turn before idle, abort without sending and retain that result. A passing callback requires native observed idle, a new lead turn whose first user input matches the exact delivery batch/nonce, and actual root receipt. Never count a new turn alone as proof or interrupt the root to manufacture idle.
